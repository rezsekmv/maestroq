# Changelog

All notable changes to `maestroq`, `@maestroq/daemon`, and `@maestroq/core` are recorded here. From v0.1.1 onward, entries are generated by [Changesets](https://github.com/changesets/changesets).

## v0.1.0 — 2026-05-17

Initial public release.

### Features

- Single daemon per machine that owns a pool of simulators / emulators
- FIFO queue per device; parallel dispatch across devices
- `maestroq init` — auto-discovers booted devices and scaffolds a runnable `maestroq/smoke-<platform>.yaml`
- Full job lifecycle: device boot/check → build (with dirty-tree cache bypass) → Metro (dev-client only) → maestro run → teardown
- Process-group isolation for cancel + crash recovery (SIGKILL by pgid)
- Finalize watchdog that handles the parallel-maestro JVM hang on Maestro 2.5.1
- `maestroq status` with short/long views, `--header`, `--watch`, `--since`, `--limit`, `--all`, status-based colors
- Claude Code skill bundled at `integrations/claude-code/SKILL.md`

### Known limitations

- Multi-iOS-sim parallelism is v0.2 work — today the daemon serializes per registered device
- Linux + macOS only; Windows is not in scope for v0.1
- Physical devices work in theory but are untested
- Remote / TCP transport is deferred to v1.0; Unix socket only

[Full release notes on GitHub](https://github.com/rezsekmv/maestroq/releases/tag/v0.1.0).
